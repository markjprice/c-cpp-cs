> **Prompt**: Please show me how List<T> internally resizes itself.

Under the hood, C#'s `List<T>` is **not** a linked list. It is a wrapper around a standard, fixed-size C# array (`T[]`) along with an integer tracking how many slots are currently used.

Because arrays in .NET have a fixed length that cannot be changed once allocated, `List<T>` simulates growth by allocating a completely new, larger array and copying the old elements over.

---

---

## 1. The Core State: `Count` vs. `Capacity`

Internally, `List<T>` relies on two main variables:

* **`_items` (`T[]`):** The actual fixed-size array residing in heap memory. Its length is the **`Capacity`**.
* **`_size` (`int`):** The number of elements you have added so far. This is the **`Count`**.

When you write `new List<int>()`, .NET does not allocate a giant array. It starts with an empty array of size `0`.

```csharp
// Internal representation inside .NET's List<T>
private T[] _items; // The underlying array
private int _size;  // How many items are stored (Count)

```

---

## 2. The Growth Strategy: The Doubling Rule

When you call `.Add(item)`, the list checks if `_size == _items.Length`. If the array is full, it triggers a resize:

1. **Initial Add:** If empty, it assigns a default initial capacity of **4**.
2. **Subsequent Resizes:** Every time the array runs out of room, it **doubles** the capacity ($4 \rightarrow 8 \rightarrow 16 \rightarrow 32 \rightarrow \dots$).

| Action | Stored Elements | `Count` | `Capacity` | Triggered Action |
| --- | --- | --- | --- | --- |
| `new List<int>()` | `[]` | 0 | 0 | None (empty array) |
| `.Add(1)` | `[1, _, _, _]` | 1 | 4 | Allocates array of size 4 |
| `.Add(2), .Add(3), .Add(4)` | `[1, 2, 3, 4]` | 4 | 4 | Fills existing slots ($O(1)$) |
| `.Add(5)` | `[1, 2, 3, 4, 5, _, _, _]` | 5 | 8 | **Resizes:** Allocates 8, copies 4 |

---

## 3. Step-by-Step: What Happens During a Resize

When the 5th item is added to a 4-item list, the runtime executes the following procedure:

1. **Detect capacity breach:**
The `.Add()` method evaluates `if (_size == _items.Length)`. Since $4 == 4$, it calls the internal growth method (known in .NET runtime as `Grow` or `AddWithResize`).


2. **Calculate new capacity:** Usually double the current length.
The runtime calculates `newCapacity = _items.Length == 0 ? 4 : _items.Length * 2`. In this case, $4 \times 2 = 8$.


3. **Allocate a new array:** Allocated on the managed heap.
The runtime allocates a brand-new array: `T[] newItems = new T[newCapacity];`.


4. **Copy existing elements:** Fast block memory copy.
The runtime invokes `Array.Copy(_items, newItems, _size);` to transfer items $0$ through $3$ into the beginning of the new array.


5. **Reassign the reference:** Leaves the old array for the GC.
The internal reference `_items` is pointed to `newItems`. The old array is orphaned in memory and will eventually be reclaimed by the Garbage Collector.


6. **Insert the new item:**
The new element (5) is placed at index `_size` (index 4), and `_size` is incremented to 5.

## 4. Simplified .NET Implementation

Here is a simplified version of the actual .NET source code:

```csharp
public class MyList<T>
{
    private T[] _items = Array.Empty<T>();
    private int _size = 0;
    private const int DefaultCapacity = 4;

    public void Add(T item)
    {
        if (_size == _items.Length)
        {
            Grow(_size + 1);
        }

        _items[_size] = item;
        _size++;
    }

    private void Grow(int minCapacity)
    {
        int newCapacity = _items.Length == 0 ? DefaultCapacity : _items.Length * 2;

        if (newCapacity < minCapacity)
            newCapacity = minCapacity;

        // Allocate new array and copy
        T[] newItems = new T[newCapacity];
        Array.Copy(_items, newItems, _size);
        _items = newItems;
    }
}

```

## 5. Performance Implications

* **Amortized $O(1)$ Time:** Most `.Add()` calls write to a pre-allocated index in $O(1)$ constant time. However, when a resize occurs, it takes $O(N)$ linear time to copy all existing items. Because doubling makes resizes progressively rarer, the average cost per element remains $O(1)$.
* **Garbage Collection (GC) Pressure:** Every resize throws away the previous array. If adding millions of elements without pre-sizing, dozens of intermediate arrays are discarded onto the heap.
* **The Pro Tip:** If you know roughly how many items your list will hold, pass the expected size into the constructor:

```csharp
// Allocates an array of 10,000 upfront. Zero resizes will occur!
List<int> numbers = new List<int>(10000); 

```
