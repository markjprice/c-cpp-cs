> **Prompt**: Please explain runtime polymorphism step-by-step using a game engine example.

Runtime polymorphism (also known as dynamic polymorphism or late binding) is the magic that allows a program to treat different objects as if they were the same basic type, while still triggering their unique, specific behaviors when the code actually runs.

To see how this works, let's build a combat system for a game engine (like Unity) in C#.

## 1. The Base Blueprint (The Contract)

First, we create a general `Enemy` class. We give it an `Attack()` method, but we mark it as `virtual`. This tells the compiler, *"Here is a default attack, but specific enemies are allowed to replace this behavior with their own."*

```csharp
public class Enemy 
{
    // 'virtual' means "allow child classes to override this"
    public virtual void Attack() 
    {
        Console.WriteLine("The generic enemy bumps into you! 1 damage.");
    }
}

```

## 2. The Specific Enemies (The Overrides)

Next, we create our specific enemy types. They inherit from `Enemy`, but they use the `override` keyword to replace the generic attack with their own specialized logic.

```csharp
public class Zombie : Enemy 
{
    public override void Attack() 
    {
        Console.WriteLine("Zombie bites you! You are infected.");
    }
}

public class Dragon : Enemy 
{
    public override void Attack() 
    {
        Console.WriteLine("Dragon breathes fire! 50 splash damage.");
    }
}

public class Robot : Enemy 
{
    public override void Attack() 
    {
        Console.WriteLine("Robot fires lasers! 20 piercing damage.");
    }
}

```

## 3. Spawning the Enemies (Upcasting)

In a real game, you don't have separate lists for `List<Zombie>`, `List<Dragon>`, and `List<Robot>`. That would be a nightmare to manage. Instead, the game engine creates one single list of the base type: `List<Enemy>`.

```csharp
// We create a list of the BASE type...
List<Enemy> activeEnemies = new List<Enemy>();

// ...but we fill it with the SPECIFIC types.
activeEnemies.Add(new Zombie());
activeEnemies.Add(new Dragon());
activeEnemies.Add(new Robot());

```

This is called **Upcasting**. The engine is now looking at a Dragon, but saying, *"I don't care that you're a Dragon right now; I am just going to treat you as a generic Enemy."*

---

## 4. The Execution Trace: Runtime Polymorphism in Action

Here is where the magic happens. Every frame, the game engine loops through all the enemies and tells them to attack.

Explore this visualization to see how the engine routes the generic method call to the specific implementation at runtime.

> **Key insight:** Notice that the Game Loop *never* asks "Are you a zombie?" or "Are you a dragon?". It just says "Attack", and the object figures it out.

Here is exactly what the compiler does during that loop:

1. **The Engine grabs the next enemy:** The code executes: foreach(Enemy currentEnemy in activeEnemies).
The engine pulls the first object from the list. The variable type holding it is just `Enemy`.


2. **The engine issues the generic command:** The code executes: currentEnemy.Attack();.
The engine calls the `Attack()` method on the generic `Enemy` reference.


3. **The runtime checks the Virtual Method Table (V-Table):**
*This is the runtime polymorphism.* Because the base method was marked `virtual`, the program does not immediately run the generic `Enemy.Attack()` code. Instead, it pauses and looks at the *actual physical object* sitting in memory.


4. **The runtime routes to the override:**
It sees that the object in memory is actually a `Zombie`. It looks at the Zombie's blueprint, finds the `override void Attack()`, and executes that specific code instead.


5. **Output generated:**
The console prints: `"Zombie bites you! You are infected."` The loop then moves to the next generic reference, finds a `Dragon` in memory, and triggers the fire breath.


## Why is this so powerful?

Without runtime polymorphism, your game loop would look like a giant, messy switch statement:

```csharp
// BAD: How you would have to write code without Polymorphism
foreach (var enemy in activeEnemies) 
{
    if (enemy is Zombie) { ((Zombie)enemy).Bite(); }
    else if (enemy is Dragon) { ((Dragon)enemy).BreatheFire(); }
    else if (enemy is Robot) { ((Robot)enemy).FireLaser(); }
}

```

With polymorphism, if you add a new `Vampire` enemy to your game tomorrow, **you don't have to touch your game loop at all.** You just create the `Vampire` class, override `Attack()`, and drop it in the list. The runtime handles the rest automatically.
