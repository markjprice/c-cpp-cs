> **Prompt**: Please explain expression-bodied properties and methods with examples from production code.

Expression-bodied members are a C# syntax feature that allows you to write methods, properties, and other class members in a highly condensed, single-line format using the **fat arrow (`=>`)** operator.

In production codebases, developers use them constantly to reduce "boilerplate" code—specifically, eliminating unnecessary curly braces `{ }` and the `return` keyword. This makes classes denser and easier to scan without scrolling.

*Note: While they use the same `=>` symbol as LINQ lambda expressions, they are a structural feature of the class, not anonymous functions.*

Here is how they are used in real-world production scenarios.

---

## 1. Expression-Bodied Methods

Whenever a method consists of a single statement (especially a single `return` statement), it is a perfect candidate for an expression body. This is extremely common in Repository patterns, API Controllers, and factory methods.

**The Old Way (Standard Method):**

```csharp
public async Task<Customer> GetCustomerByIdAsync(Guid customerId)
{
    return await _dbContext.Customers.FindAsync(customerId);
}

```

**Production Code (Expression-Bodied):**

```csharp
public Task<Customer> GetCustomerByIdAsync(Guid customerId) => 
    _dbContext.Customers.FindAsync(customerId);

```

*Notice how the braces and `return` keyword are gone. The compiler automatically understands that the result of the right side should be returned.*

## 2. Read-Only Properties (Computed Properties)

In Domain-Driven Design, entities often have properties that compute their value based on other fields (like combining names or calculating eligibility). An expression-bodied property implicitly creates a read-only (`get`-only) property.

**The Old Way:**

```csharp
public bool IsEligibleForUpgrade
{
    get 
    { 
        return AccountBalance > 10000 && MonthsActive >= 12; 
    }
}

```

**Production Code:**

```csharp
public bool IsEligibleForUpgrade => AccountBalance > 10000 && MonthsActive >= 12;

```

*This is one of the most popular uses of expression bodies because it reduces a 6-line property into a single, highly readable line.*

## 3. Properties with Getters and Setters

When working with architectures like MVVM (Model-View-ViewModel) in WPF or MAUI, properties often require logic in their setters (like triggering a UI update). You can use expression bodies for both the `get` and `set` accessors to keep the view model clean.

**Production Code (MVVM Property):**

```csharp
private string _searchQuery;

public string SearchQuery
{
    get => _searchQuery;
    set => SetProperty(ref _searchQuery, value); // Method updates value and notifies UI
}

```

## When NOT to use them

While expression-bodied members are elegant, production guidelines usually dictate a **"One-Line Rule"**.

If the logic on the right side of the `=>` is so complex that you have to break it into multiple heavily indented lines with complex ternary operators (`? :`), you should revert to standard curly braces. The goal is readability, and cramming a 500-character logical puzzle into an expression body defeats the purpose.
