> **Prompt**: Please explain object-oriented programming in C# using a real-world analogy that compares classes, objects, interfaces, and inheritance.

To understand Object-Oriented Programming (OOP) in C#, imagine you are running an **automobile manufacturing company**.

Instead of writing code as one long, confusing list of instructions, OOP lets you organize your code around real-world concepts (like cars) and how they interact.

---

## 1. Classes (The Blueprint)

A **Class** is the engineering blueprint for a car. You cannot drive a blueprint, but it defines exactly what a car *has* (data/properties) and what a car *does* (behavior/methods).

```csharp
// The Blueprint
public class Car 
{
    // What it HAS (Properties)
    public string Color { get; set; }
    public string Model { get; set; }

    // What it DOES (Methods)
    public void StartEngine() 
    {
        Console.WriteLine("Vroom!");
    }
}

```

## 2. Objects (The Actual Car)

An **Object** is the physical car that rolls off the assembly line. Using one class (blueprint), you can build thousands of objects. Each object is independent—if you paint one car red, it doesn't change the color of the other cars. Creating an object is called *instantiation*.

```csharp
// Rolling cars off the assembly line
Car myHonda = new Car();
myHonda.Model = "Civic";
myHonda.Color = "Red";

Car yourFord = new Car();
yourFord.Model = "Mustang";
yourFord.Color = "Blue";

myHonda.StartEngine(); // Output: Vroom!

```

## 3. Inheritance (The Specialized Blueprint)

Imagine you want to start building delivery trucks. A truck is still a type of vehicle—it has an engine and a color just like a car—but it also has new features, like a cargo bed.

Instead of redrawing a whole new blueprint from scratch, **Inheritance** allows you to create a new `Truck` blueprint that automatically inherits everything from the `Car` blueprint, and then adds its own special features.

```csharp
// Truck inherits everything from Car
public class Truck : Car 
{
    // The Truck adds its own specific property
    public int CargoCapacityKg { get; set; }

    public void LoadCargo() 
    {
        Console.WriteLine("Loading boxes...");
    }
}

// Creating a Truck object
Truck deliveryTruck = new Truck();
deliveryTruck.Color = "White";      // Inherited from Car!
deliveryTruck.StartEngine();        // Inherited from Car!
deliveryTruck.LoadCargo();          // Specific to Truck

```

## 4. Interfaces (The Capability / Certification)

An **Interface** is like a standard certification or a specific capability. It isn't a blueprint for a whole car; it is just a contract that says, *"If you claim to have this capability, you MUST include these specific features."*

For example, not all cars are electric. But if a vehicle claims to be plug-in electric, it *must* have a way to charge. We can create an `IElectricChargeable` interface (interfaces usually start with 'I' in C#).

```csharp
// The Contract / Certification
public interface IElectricChargeable 
{
    // It doesn't say HOW to charge, just that it MUST be able to charge
    void PlugInToGrid(); 
}

// A new class that inherits from Car AND implements the Interface
public class Tesla : Car, IElectricChargeable 
{
    public void PlugInToGrid() 
    {
        Console.WriteLine("Connecting to Supercharger...");
    }
}

```

> **The Big Picture:** The `Car` **class** is your blueprint. The `Tesla` **object** in your driveway is the physical result. **Inheritance** lets a `Truck` borrow the `Car` blueprint to save you time. **Interfaces** ensure that any vehicle claiming to be electric actually has a charging port.
