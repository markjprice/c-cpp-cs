> **Prompt**: Compare constructors, object initializers, and primary constructors in modern C#.

Modern C# offers multiple ways to initialize an object, each evolving to solve a specific problem.

* **Traditional Constructors** give you total control and logic.
* **Object Initializers** give you flexible syntax for data-heavy objects without needing dozens of constructor overloads.
* **Primary Constructors** (introduced in C# 12) remove boilerplate code by attaching parameters directly to the class name.

Here is how they compare in practice.

---

## 1. Traditional Constructors (The Heavyweight)

A traditional constructor is a method with the same name as the class. It is the most robust way to set up an object because it guarantees the object is fully configured before anyone can use it.

**When to use:** Dependency Injection, complex validation logic, or when initialization requires multiple steps.

```csharp
public class UserService 
{
    private readonly ILogger _logger;
    public string Role { get; }

    // Traditional Constructor
    public UserService(ILogger logger, string role) 
    {
        // You have total control here to run logic/validation
        if (string.IsNullOrWhiteSpace(role)) 
            throw new ArgumentException("Role is required.");

        _logger = logger;
        Role = role;
    }
}

// Usage:
var service = new UserService(myLogger, "Admin");

```

## 2. Object Initializers (The Flexible Setter)

Object initializers let you assign values to accessible properties or fields at the exact moment of creation, using curly braces `{ }`.

Historically, this required properties to have `set` accessors, which made them mutable (changeable later). Modern C# (C# 9+) introduced `init`-only properties, allowing you to use object initializers while keeping the object immutable after creation.

**When to use:** DTOs (Data Transfer Objects), API payloads, configurations, or classes with many optional properties where writing a traditional constructor for every combination would be a nightmare.

```csharp
public class UserDto 
{
    // 'init' means it can ONLY be set during object initialization
    public string FirstName { get; init; } 
    public string LastName { get; init; }
    public int Age { get; init; }
}

// Usage (Object Initializer):
var user = new UserDto 
{
    FirstName = "Alice",
    LastName = "Smith",
    // Age is optional, we don't have to provide it
};

```

## 3. Primary Constructors (The Modern Shortcut)

Introduced for classes in C# 12 (they already existed for Records), primary constructors allow you to define constructor parameters directly on the class name. It eliminates the boilerplate of writing a constructor body just to assign parameters to private fields.

**When to use:** Dependency Injection where you just need to store the injected services, or simple data classes where parameters don't require complex validation.

```csharp
// Primary Constructor parameters (logger, role)
public class UserService(ILogger logger, string role) 
{
    // The parameters 'logger' and 'role' are automatically captured 
    // and can be used anywhere in the class.
    
    public void DoWork() 
    {
        logger.Log("Work started by: " + role);
    }
}

// Usage:
var service = new UserService(myLogger, "Admin");

```

## Feature Comparison Matrix

| Feature | Traditional Constructors | Object Initializers | Primary Constructors |
| --- | --- | --- | --- |
| **Boilerplate Code** | High (Fields, assignments, `{}`) | Low (Just `{ Prop = val }`) | Lowest (Class-level params) |
| **Supports Validation Logic** | **Yes** (Inside the `{ }` body) | **No** (Direct assignment only) | **Limited** (Requires extra steps) |
| **Handles Optional Parameters Well** | **No** (Requires many overloads) | **Yes** (Just don't set the prop) | **No** (All params usually required) |
| **Dependency Injection** | Industry Standard | Rarely Used | The New Standard (C# 12+) |
| **Immutability Support** | Yes (`readonly` fields) | Yes (via `init` properties) | Yes (captured variables) |
