> **Prompt**: Please explain constructor chaining visually with a step-by-step execution trace.

Constructor chaining happens when a constructor calls another constructor before it executes its own code. It prevents you from writing the same setup logic multiple times.

You can chain to a constructor in the same class using `this(...)`, or chain to a constructor in a parent class using `base(...)`.

The most important (and sometimes confusing) rule of constructor chaining is the **execution order**: *the chain goes all the way up to the top first, and then the actual code inside the constructors runs top-down.*

Here is the setup we will trace:

```csharp
public class Entity 
{
    public Entity() 
    {
        Console.WriteLine("Body A: Entity Setup");
    }
}

public class User : Entity 
{
    // Constructor 1: Takes a name
    public User(string name) : base() 
    {
        Console.WriteLine($"Body B: User Setup for {name}");
    }

    // Constructor 2: Default, passes a default name to Constructor 1
    public User() : this("Guest") 
    {
        Console.WriteLine("Body C: Default User Setup");
    }
}

```

## Step-by-Step Execution Trace

Here is exactly what the compiler does, step-by-step, when you execute `new User();`:

1. **Call the initial constructor:**
The application requests a `new User()`. The compiler hits the parameterless `User()` constructor.


2. **Follow the 'this' chain:** Delegating to the overloaded constructor.
Before running any code inside `User()`, the compiler sees `: this("Guest")`. It immediately halts execution of `User()` and jumps over to `User(string name)`, passing in "Guest".


3. **Follow the 'base' chain:** Delegating to the parent class.
Before running any code inside `User(string name)`, the compiler sees `: base()`. It halts execution again and jumps up to the parent `Entity()` constructor.


4. **Execute Entity body:**
The `Entity()` constructor has no other constructors to chain to (other than the invisible global `Object` class). It finally executes its code.
*Output:* `"Body A: Entity Setup"`


5. **Execute User(string) body:**
Now that the parent is fully set up, the compiler falls back down to finish `User(string name)`.
*Output:* `"Body B: User Setup for Guest"`


6. **Execute original User() body:**
Finally, the compiler returns to the very first constructor you called to finish its remaining code.
*Output:* `"Body C: Default User Setup"`
