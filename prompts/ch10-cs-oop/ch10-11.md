> **Prompt**: What is method hiding with new in C#, and how is it different from override?

The difference between `override` and `new` (method hiding) comes down to one question: **Who gets to decide which method runs—the actual physical object in memory, or the variable type holding it?**

* **`override` (Polymorphism):** Replaces the base method. The program looks at the *actual object* in memory and runs the newest, overridden version of the code.
* **`new` (Method Hiding):** Creates a completely separate method that happens to have the same name. The program looks at the *variable type* to decide which one to call, ignoring what the actual object is.

---

## 1. The Code Example

Let's look at a `SmartPhone` that inherits from a basic `Phone`.

* We will **override** the `Ring()` method (because the base method was marked `virtual`).
* We will **hide** the `ConnectToNetwork()` method using `new` (because the base method wasn't `virtual`, but we want to change it anyway).

```csharp
public class Phone 
{
    // 'virtual' allows us to override this
    public virtual void Ring() 
    {
        Console.WriteLine("Ring ring!");
    }

    // No 'virtual' keyword. It's a standard method.
    public void ConnectToNetwork() 
    {
        Console.WriteLine("Connecting to 3G...");
    }
}

public class SmartPhone : Phone 
{
    // OVERRIDE: Replaces the Ring method entirely
    public override void Ring() 
    {
        Console.WriteLine("Playing custom MP3 ringtone!");
    }

    // NEW (HIDING): Creates a brand new method that shadows the old one
    public new void ConnectToNetwork() 
    {
        Console.WriteLine("Connecting to 5G...");
    }
}

```

---

## 2. The Execution: Where the Difference Appears

If you create a `SmartPhone` and store it in a `SmartPhone` variable, both methods will do exactly what you expect (run the new 5G and MP3 code).

**The critical difference only shows up when you store the `SmartPhone` in a generic `Phone` variable (Upcasting).**

```csharp
// We create a SmartPhone object, but store it in a base Phone reference
Phone myPhone = new SmartPhone();

// 1. Testing the Override
myPhone.Ring(); 
// Output: "Playing custom MP3 ringtone!" 
// (The runtime looks at the actual object and sees it's a SmartPhone)

// 2. Testing the Hide (new)
myPhone.ConnectToNetwork(); 
// Output: "Connecting to 3G..."
// (The compiler just looks at the variable type 'Phone' and calls the base method. 
// It completely ignores that the object is actually a SmartPhone.)

```

## Summary Comparison

| Feature | `override` | `new` (Method Hiding) |
| --- | --- | --- |
| **What it does** | Replaces the base class behavior. | Disconnects from the base class and creates a new, independent method. |
| **Base Method Requirement** | Base method *must* be marked `virtual` or `abstract`. | Base method does not need to be `virtual`. |
| **How it resolves** | **Runtime:** Looks at the actual object in memory. | **Compile-time:** Looks at the variable/reference type. |
| **When to use it** | Standard OOP polymorphism (99% of the time). | When a base class (that you don't control) adds a new method that accidentally shares a name with your existing method, or you specifically want to block polymorphism. |
